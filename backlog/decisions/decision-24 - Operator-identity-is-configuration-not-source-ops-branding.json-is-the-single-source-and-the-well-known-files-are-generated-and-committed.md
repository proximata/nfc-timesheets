## Context

The owner asked to make both apps "ready to be deployed on behalf of any signing entity". That
is not mainly an Xcode problem. The operator's identity is baked into files the **server**
serves, and into source spread across four directories:

- `server/wellknown/apple-app-site-association` carried the literal
  `6Y842FE8Q4.io.github.qwadratic.NFCTimeSheets` — team id **and** bundle id.
- `server/wellknown/assetlinks.json` carries the Android package name and must carry the
  SHA-256 fingerprints of the Android signing certificates.
- The tag host `timesheets.exe.xyz` appeared as a literal in six load-bearing places:
  `NFCTimeSheets.entitlements:16`, `TagLink.swift:19`, `API.swift:21`, `web/lib/tag.ts:11`,
  and the two served association files. Plus `verify.sh`, `deploy.sh` and
  `routes/wellknown.test.js` as defaults and assertions.

A different company signing and shipping this needs **their** team id, **their** bundle and
application id, **their** certificate fingerprints and **their** host. Before this record that
meant hand-editing source in a dozen places and getting every one of them consistent.

The failure mode is what forced the decision. **A mismatch between any of those values and the
association file served from the host does not error.** iOS silently opens Safari; Android
silently opens Chrome. No crash, no log, no red build. What the operator sees is a worker
standing at a door unable to clock in — and the tags are already glued to walls.

## Decision

**Operator identity is configuration. `ops/branding.json` is the single source of truth, and
nothing in the repo is permitted to disagree with it.**

1. **`ops/branding.json`** holds `host`, `appName`, `apple.teamId`, `apple.bundleIds`,
   `apple.paths`, `android.packageName`, `android.sha256CertFingerprints`. Committed,
   hand-edited, read by tooling only. **Nothing reads it at runtime**, so the server gains no
   boot dependency and no npm dependency (decision-16 as amended by decision-23 holds: `pg` +
   `@sentry/node`, nothing else). `ops/gen-wellknown.mjs` and `ops/check-branding.mjs` are node
   stdlib and run on a developer machine.

2. **The two association files are generated by `ops/gen-wellknown.mjs` AND committed.** Not
   generated at deploy time. AASA is the most dangerous file in this product and a human must
   be able to read the exact bytes in a `git diff` **before** they reach a wall; deploy-time
   generation hides them behind a script and moves the review to a moment when nobody is
   looking. `deploy.sh` step 0 only *asserts* that the committed bytes match the config, so the
   artifact that ships is the one that was read.

3. **The AASA appID list is APPEND-ONLY.** Apple caches AASA and an installed app holds its
   association until reinstall. Dropping an appID bricks every installed copy of that app, and
   the operator cannot uninstall it from a worker's phone. A handover appends. The generator
   refuses to remove a published appID without an explicit `--allow-removal`.

4. **`android.sha256CertFingerprints` is plural and format-validated.** With Play App Signing
   on — the default — the upload key and the Play signing key are different certificates and
   both must be listed. Format is enforced as uppercase colon-separated 32-byte hex, because a
   lowercase fingerprint is valid JSON and is then **silently ignored** by Android's verifier.
   The Play signing fingerprint comes from Play Console → Release → Setup → App signing, never
   from `keytool`, which only knows the local key.

5. **iOS gets one config file plus one checked mirror, and it is INERT by default.**
   `NFCTimeSheets/Branding.xcconfig` carries `TS_TEAM_ID`, `TS_BUNDLE_ID`, `TS_APP_NAME`,
   `TS_TAG_HOST` and is **not referenced by the project**. `TS_TAG_HOST` reaches Swift through
   the `TSTagHost` Info.plist key; `Branding.swift` treats missing, empty, whitespace and an
   unsubstituted `$(VAR)` all as unconfigured and falls back to today's literals. With nothing
   attached the app is byte-identical in behaviour to the current TestFlight build.
   `checks/tag-link-check.swift` pins that contract.

6. **`NFCTimeSheets.entitlements` keeps a LITERAL host, deliberately.** `applinks:$(TS_TAG_HOST)`
   does substitute — but an **undefined** Xcode build setting expands to the **empty string**,
   so any build without the xcconfig attached would emit `applinks:` and kill universal links
   on the next build, green and silent, shippable to TestFlight. Templating it would be the
   exact "white-label knob that breaks day one" case on the worst possible surface. Instead
   `ops/check-branding.mjs` asserts the entitlement mirrors `branding.host`, and editing it is
   a named manual step in `ops/REBRAND.md`.

7. **`project.pbxproj` is never touched by tooling.** The owner hand-edits it. `ops/REBRAND.md`
   carries the exact Xcode click path instead, including the non-obvious part: target-level
   `PRODUCT_BUNDLE_IDENTIFIER` and `DEVELOPMENT_TEAM` beat a project-level xcconfig and must be
   deleted, or the xcconfig is silently ignored for those two settings.

8. **Android reads `android/branding.properties`;** keystores and passwords are never committed
   (`android/keystore.properties`, gitignored), with a debug-signing fallback so a fresh clone
   builds and Play refuses the result — a loud failure.

9. **Credentials are NOT identity and stay out of `branding.json`.** The app key
   (`Branding.swift` / `ts.appKey` / `/etc/nfc/env`) and the Sentry DSN keep their existing,
   documented homes. A third copy would only be a third thing to desync, and neither is a
   secret (both are compiled into the binary and already reasoned about in place).

10. **`server/wellknown/verify.sh` byte-compares live against the reviewed files** and reads
    the host from `branding.json`. It contains **zero** identity literals. A substring match
    ("does the AASA mention our appID?") passes on a file that *also* carries a stale appID or
    a widened `paths`, so the comparison is byte-for-byte. `deploy.sh` already treats it as a
    hard gate; it now also runs `gen-wellknown` + `check-branding` as step 0, before the build
    and before any rsync.

11. **`node ops/check-branding.mjs` is the single runnable check** over the whole surface: both
    association files, the entitlement, the xcconfig, the Swift fallbacks, `APPLE_AUDIENCE`,
    `web/lib/tag.ts`'s default, `android/branding.properties`, and two anti-drift rules — the
    team id appears in no source file, and the host has exactly one home in Swift.

**Defaults reproduce today's deployment exactly.** Verified: the generated files are
byte-identical (sha256 `eb3b99b0…` / `ec362540…`) to both the committed files and the bodies
live at `https://timesheets.exe.xyz` at the time of writing.

## Consequences

**Good.**

- A new signing entity edits one JSON file, one xcconfig, one properties file and one
  entitlement line, and two commands tell them whether they got it right.
- The failure that costs a site visit is now gated three times: at generation (append-only,
  format validation), at deploy (step 0), and against the live host (`verify.sh` byte compare).
  Every gate was mutation-tested, not merely asserted.
- The iOS app is unchanged in behaviour with nothing wired up, so this could land while a tap
  fix was mid-verification on TestFlight. Zero bytes of `project.pbxproj` changed.
- No new server dependency, no new server endpoint, no new runtime file read.

**Costs, stated plainly.**

- **The entitlement is a mirror, not a derivation.** It can go stale between an edit and the
  next `check-branding` run. That is a real hole and it is accepted knowingly: the alternative
  templating breaks the app when the xcconfig is *absent*, which is strictly worse.
- **Four values still need a human in Xcode** (attaching the xcconfig, clearing two
  target-level rows on three targets). No tooling can do it while `project.pbxproj` is
  hand-edited.
- `check-branding.mjs` reads the xcconfig, plist and properties formats with one regex each.
  A value containing `#`, a quoted plist entity or a properties line continuation would be
  misread. Upgrade path: `plutil -convert json` and a real properties parser.
- Two literals are duplicated on purpose and guarded by the check rather than eliminated:
  `web/lib/tag.ts`'s default (so `web/` stays buildable standalone and the value is baked into
  a static export) and `Branding.swift`'s fallbacks (so an unconfigured build works).

**What this does NOT solve, and must be said in these words.**

> **White-labelling makes the host a variable. It does not make deployed tags re-pointable.**
> Tags are unlocked (decision-15) so a rewrite is physically possible, but it is a site visit
> per building. Configuration is cheap only for an operator starting at **zero tags**. A new
> operator picks the host on day zero. decision-15's own revisit trigger — own the domain
> "before the first paying client" — is still open.

**Also unchanged:** `applicationId` is immutable once uploaded to Play, and
`server/wellknown/assetlinks.json` already publishes `io.github.qwadratic.NFCTimeSheets`. That
value was kept rather than lower-cased, so zero bytes of a file that gates physical tags moved.
